# Moonlit Ride — Unity port

Playable native Windows port of the procedural Three.js game, using **Unity 6000.3.17f1** and the built-in render pipeline. Open this `Unity` directory as a Unity project, open `Assets/Scenes/MoonlitRide.unity`, and press Play. The scene creates the coast and rider at runtime, so its edit-mode hierarchy is intentionally small.

## On this computer

- `Builds/Windows/MoonlitRide.exe` — standalone game after building.
- `Open-Unity.ps1` — opens the installed matching Editor.
- `Build-Windows.ps1` — imports the project, runs regression checks, then builds Windows.
- Editor menu **Moonlit Ride → Run port regression checks** runs the C# checks.
- Editor menu **Moonlit Ride → Validate and build Windows** produces the standalone player.

No paid assets, third-party Unity packages, network services, or downloaded audio are required. A valid Unity Editor license is needed to edit or build; the standalone player does not need Unity installed. Generated caches and builds are excluded from Git. Keep the executable beside its `_Data` folder, `UnityPlayer.dll`, and `MonoBleedingEdge` directory.

## Controls

Enter / Let's ride starts. A/D or arrow keys steer; W/up pedals harder; S/down brakes; Shift coasts. Space, Escape, or Pause pauses/resumes; R restarts. Automatic pedaling remains enabled when no pedal/brake/coast key is held. Focus loss pauses the ride.

The bottom bar controls sound, volume, reduced motion, and on-screen touch buttons. Sound, volume, and reduced motion are saved locally; ride progress is session-only. Reduced motion is an explicit Unity setting; the browser's automatic OS preference detection has not been ported.

## Ported behavior

- Original 120 Hz force model, now scheduled by Unity `FixedUpdate` before native secondary physics; gentle steering, level camera horizon, braking, climbing assistance, wheel travel, and speed-dependent posture.
- Repeating 720 m hills: 480 m descent and 240 m climb. Streamed coast retains 23 chunks and combines static geometry by material.
- Five rows of six gold fireflies on each descent: +1 each and +5 for a complete row, once only. Mint booster at 478 m adds 10 m/s (capped at 30) and nine seconds of decaying thrust. Braking cancels the boost.
- Houses are on the **right**, the sea on the **left**, matching the browser scene. The original coordinate system is converted at the rendering boundary; controls, camera, road geometry, scenery winding/normals, and pickups follow the same conversion.
- Procedural houses with mullions, shutters and planters; textured paving with a normal map, railings, lamps, pines, boats, water and headlands.
- Blender-authored rider with a CC0 MakeHuman anatomical body: pleated botanical dress with an integrated indigo hem, fitted bodice, shaped head, swept hair strands, and a continuous three-strand braid. Source and regeneration instructions are in `../art/`.
- Native **Unity Cloth** uses a pinned waistband, graded motion limits, tethers, self collision, continuous capsule collision, and hip/leg envelopes. The printed hem belongs to the cloth mesh, so it cannot detach.
- The braid is a **SkinnedMeshRenderer** driven by 12 **Rigidbody / ConfigurableJoint** bones, with angular limits, damping, torso collision and a kinematic head attachment. A **WindZone** supplies coastal wind settings; `RiderDynamics` explicitly maps those settings plus apparent wind from bicycle speed to Cloth acceleration and rigidbody forces. WindZone does not automatically drive these components.
- Pause freezes native physics through the scaled Unity clock. Restart resets cloth motion and all braid bodies. Reduced motion lowers turbulence while retaining the physical drape.
- Pooled pickup feedback, pause/reset behavior, a local polyphonic ambient synthesizer, wind, and chord-matched pickup notes. Music softens on pause; simulation and visual effect clocks freeze.

## Verification

`PortChecks.cs` checks physics, route seams, row awards, boost, chord transitions, cloth/braid stability, and frame-rate independence. Eighteen reference fixtures generated by the original JavaScript physics check C# parity with numeric tolerances for float arithmetic. Regenerate after intentional physics changes with `node scripts/export-unity-fixtures.mjs` from the repository root.

Run the built game with `-moonlitSmoke -moonlitCapture <absolute-png-path> -logFile <absolute-log-path>` for the actual-scene smoke check: ride progression, collection/bonuses, chunk bounds, pause across frames, restart, screen-space steering, scene orientation, and native wind response. The test compares calm and windy cloth/braid poses, checks waistband and rendered braid attachment, then stresses a fast ride and abrupt stop. It saves an offscreen camera image and a `-rider.png` close-up (without the IMGUI overlay). Look for `MOONLIT_NATIVE_WIND_PASSED`, `MOONLIT_RUNTIME_SMOKE_PASSED`, and a zero exit code.

## Source map and current limits

`RideSimulation.cs` owns ride state and route rules; `CoastalWorld.cs` streams scenery; `BicycleView.cs` poses the bicycle/rider; `RiderDynamics.cs` configures native cloth, braid joints and wind; `MoonlitGame.cs` coordinates input/UI/camera/lifecycle; `RideAudio.cs` synthesizes audio; `PickupFeedback.cs` owns the effects pool. `SecondaryMotion.cs` is retained only as the original browser-port regression reference and is no longer used by the rider.

Unity uses different lighting/materials and a native synthesizer; stars, speed streaks and Web Audio convolution reverb are not reproduced exactly. This remains stylized artwork rather than a production character rig. Body collision envelopes are approximate; cloth is not a full garment/body solver. The UI currently uses IMGUI. World geometry is mostly generated in code. Floating-origin support and long-session/device performance profiling remain future work. Windows is the initial tested target; physical touch hardware and mobile builds need separate testing.

Native component references: [Unity Cloth](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Cloth.html), [ConfigurableJoint](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/ConfigurableJoint.html).

## Realism and posture follow-up

The head now uses the CC0 MakeHuman adult female base anatomy, fitted in Blender to the hairstyle. The full clothed body uses MakeHuman anatomy and skin weights; materials and clothing remain stylized. Provenance is in `../THIRD_PARTY_ASSETS.md`. Arms and legs use analytic two-bone IK with stable elbow/knee poles; hands stay at the handlebar and feet track the crank cycle. Forward posture responds smoothly to speed, positive acceleration and boost, pivoting at the waist. Moving thigh collision capsules follow IK and influence Unity Cloth; bending stiffness is lower and the hem has more freedom.

Walkways use continuous swept bevelled profiles along the route. The sea uses a planar reflection camera with an oblique clipping plane, Fresnel reflection, filtered multi-scale noise normals and directional highlights. Warm nearby lantern point lights illuminate the road against a cooler ambient sky. Reflection costs an extra camera render; distant lantern lights are disabled. Water remains a flat shaded surface, without simulated breaking waves or underwater refraction.

AnatomicalRider now supplies the full clothed MakeHuman body with a 14-bone SkinnedMeshRenderer rig. It uses the original CC0 skin weights reduced to the cycling skeleton, driven by the existing analytical IK. Shoulders, back, waist, hips and limbs retain anatomical topology instead of primitive cylinders. The black blouse is expanded and smoothed from the anatomical surface; the skirt is simulated separately.

Distance haze begins at 100 m and fully blends geometry at 340 m. Sky horizon shading uses the same Unity fog colour; the near rider and road stay clear. Standard, fabric, glow and water materials participate in fog, including the reflection camera.

## Reference-led character pass

The rider uses a vivid blue seven-turn braid, a loose black blouse with small pale flecks, a white skirt with cobalt botanical ornament, rounded shoes and a baked finger grip. Subtle cadence-driven shoulder sway shares the same posture transform as the head and arm IK. Unity Cloth receives time-varying crosswind and lift at ordinary riding speeds; torso collision follows the pose and braid damping uses measured attachment velocity.

Dress topology is welded across the full circumference. The fabric shader reconstructs cylindrical UVs from angular coordinates in UV0 and height in UV1, avoiding split simulation vertices at a texture seam. PortChecks verifies that only the waistband and hem have boundary edges. Runtime smoke additionally checks >8 cm motion at 10 m/s and captures 16 frames while the rider pedals, suitable for a movement preview.

CoastalBloom adds restrained light bloom and colour grading. The reference palette includes cobalt water/sky and facades, warm continuous paving, curved gables, window arches, flowers and fuller seaside foliage.

## Nature assets and faster Unity riding

The Unity ride uses an assisted arcade speed profile: approximately 80 km/h automatic cruise, 90 km/h while W/up is held, and up to 140 km/h during the existing mint booster. Braking cancels the booster and stops the bicycle; coasting retains gravity and drag. These are actual simulation speeds, not a HUD multiplier. The original browser profile remains in StepOnRoad's default mode solely for parity coverage. The additional fast-profile checks verify uphill cruise, reaching the boost limit and downhill braking.

Quaternius Ultimate Stylized Nature CC0 trees, bushes, grass and rocks replace the primitive trees. See THIRD_PARTY_ASSETS.md for attribution and provenance. NatureImporter preserves readable mesh data for per-material chunk combining; NatureAssets retains the original FBX import transforms. Foliage uses alpha-cutout textures and subtle wind. The continuous bank varies along the coast, placing vegetation on its surface; boats sit offshore. Water includes a shallow-water tint and a soft foam edge. Runtime smoke captures an additional `-shore.png` overview and stresses secondary physics at 140 km/h.

## Waterfront districts

Each 720 m loop now contains three 240 m districts, selected deterministically from route progress. The market has dense mixed-height shops with display windows, striped awnings, produce crates and lantern strings. The residential quarter has smaller pitched-roof houses, front gardens, fences, mailboxes, balconies and pocket gardens with benches. The tourist quarter combines hotels, roof terraces, balcony railings, cafe plazas with parasols, information boards and waterfront telescopes.

Two piers per loop occupy the tourist quarter. Stone stairs connect the promenade to wooden walkways and mooring docks; the bank is cut below the stairs, and rocks/vegetation are excluded from their access corridor. Boats use shaped hull meshes with three variants: sailboats, fishing launches and runabouts, including rigging, seats/cabins, fenders and mooring ropes. Boats are static scenery. The cycle corridor and 80/90/140 km/h speed profile are unchanged.

`CoastalDistricts.cs` extends the procedural world; `DistrictAt` and `HasPier` are checked for loop boundaries and pier counts. Runtime smoke captures fixed district and marina viewpoints in addition to the normal ride and character views.

## City bicycle

The primitive frame and wheels are replaced by an adapted city bicycle by Poly by Google (CC BY 3.0; see THIRD_PARTY_ASSETS.md). It has a curved step-through frame, fenders, smooth tan-wall tires, metal rims, crossed spokes, leather grips/saddle, a chain, rear carrier and lamps. Five imported FBX parts are controlled by CityBicycle: steering/fork, front and rear wheels, crank and level pedals. Hand IK follows the grips during steering, and the feet share the pedal trajectory. The arcade speed profile is unchanged.

Rebuild the assets with Blender --background --python art/build_bicycle.py from the repository. Original and separated source assets live in art/third-party/poly-bicycle; art/CityBicycle.blend is the editable adaptation. BuildWindows includes THIRD_PARTY_ASSETS.md beside the player. Smoke captures Bicycle-detail.png in addition to the existing visual checks.

## WebGL and GitHub Pages

The main site is the Unity WebGL edition; the original Three.js game is retained at `classic/`. Install **Web Build Support** for Unity 6000.3.17f1. From the repository, invoke Unity with:

```text
Unity -batchmode -quit -buildTarget WebGL -projectPath Unity -executeMethod MoonlitRide.Editor.ProjectSetup.BuildWebGL -logFile webgl-build.log
npm run build:pages
npm run package:unity-pages
```

`BuildWebGL` validates PortChecks and writes a release build to ignored `Unity/Builds/WebGL`. `package:unity-pages` checks the generated loader and GitHub file limits before copying it into tracked `docs/`. Commit the resulting files and push `main`; Pages serves `main:/docs`. Do not overwrite the root with the old browser packager: `build:pages` now targets `docs/classic/`.

Gzip plus decompression fallback works on GitHub Pages without custom HTTP headers. Hashed build filenames avoid stale cached WASM/data after updates. The custom template provides loading/error states, full screen, credits and a link to the original edition. The compiled download is approximately 11 MB. WebGL 2 and desktop browsers are the initial web target; physical mobile-device performance has not been validated.

`OnAudioFilterRead` is unsupported in WebGL, so `MoonlitAudio.jslib` calls the Web Audio counterpart in the template. It preserves harmony, pickup chimes, wind, pause attenuation and shared mute/volume, unlocks audio on a user gesture, and silences hidden tabs. `npm test` covers its lifecycle and scheduling. `Assets/MoonlitRide/link.xml` keeps BoxCollider/SphereCollider, which `CreatePrimitive` needs internally before the geometry helper removes them; IL2CPP would otherwise strip these indirect dependencies.
